# 🧭 НавигаторПедагога

Система дистанционного наставничества для молодых педагогов — с настоящим бэкендом, базой данных на SQL, кэшированием и ИИ-«цифровым наставником». Основной AI-провайдер — SmartAPI с моделью `gpt-5.6-luna`; Groq Compound остаётся резервным вариантом. ИИ выполняет диагностику, разбор рабочих ситуаций и помогает строить дорожную карту, пока человек-наставник курирует и корректирует итоговый путь.

## Роли

- **Молодой педагог** — проходит диагностику (разговор с ИИ или структурированный тест из диссертации), получает дорожную карту мероприятий по региону, отчитывается о пройденных мероприятиях.
- **Наставник** (человек) — подтверждает пару с педагогом, видит его дефициты, читает и **оценивает отчёты** — по методологии именно это и есть его роль: не выполнять диагностику и подбор самому (это делает ИИ), а корректировать и контролировать путь.
- **Администратор** — управляет каталогом мероприятий и пользователями.

## Ключевая функция: ИИ ищет мероприятия в интернете по региону

1. Педагог указывает регион при регистрации.
2. Проходит диагностику: либо разговор с ИИ-наставником по 6 компетенциям, либо структурированный тест (`/api/diagnostic/*`) с реальными пунктами из диссертации (шкала 1-3, конвертируется в привычную 1-5).
3. Бэкенд обращается к подключённой AI-модели и просит найти реальные мероприятия для молодых педагогов в указанном регионе — приоритет сайтам профсоюза образования, региональных ИРО/ИПК и министерств образования.
4. Найденные мероприятия попадают в дорожную карту, сгруппированную по дефицитным компетенциям.
5. Педагог берёт мероприятие «в работу», по завершении пишет отчёт и оценивает полезность — наставник видит отчёт и ставит свою оценку. Это и есть та самая «ручная корректировка пути».

**Без ключа SmartAPI и Groq** («офлайн-режим») приложение полностью работает — вместо живого AI показывается запасной каталог мероприятий.

## Архитектура

```
frontend/                     — статический сайт (для GitHub Pages)
backend/
  src/index.js                — точка входа, поднимает схему БД при старте
  src/db.js                   — пул подключений к Postgres (pg) + мапперы snake_case → camelCase
  src/cache.js                — простое in-memory кэширование с TTL (без Redis — бесплатно)
  src/data/schema.sql          — вся схема БД
  src/data/testBank.js         — банк вопросов диагностики (из диссертации)
  src/middleware/auth.js       — JWT-авторизация
  src/routes/                  — auth, users (+ заявки на наставника), events, notes,
                                  messages, ai (диалоговая диагностика, роадмап, чат,
                                  отчёты/оценки), diagnostic (структурированный тест)
  src/services/gemini.js       — OpenAI-совместимая обёртка SmartAPI / Groq
  src/services/roadmap.js      — генерация дорожной карты + прогресс по мероприятиям
  src/services/mentor.js       — диалоговый движок диагностики + офлайн-советник
```

**База данных — SQLite без внешнего сервиса по умолчанию**: `backend/src/data/schema.sqlite.sql`. Схема и демо-данные создаются автоматически при первом запуске. Если задан `DATABASE_URL`, приложение переключается на PostgreSQL.

**Кэширование** — простой in-memory слой с TTL (`src/cache.js`) для часто читаемых, редко меняющихся данных (каталог мероприятий, банк вопросов теста). Не требует Redis/внешней инфраструктуры — специально, чтобы весь стек оставался бесплатным. Если проект вырастет до нескольких инстансов backend — замените на Upstash Redis (тоже есть бесплатный тариф) с тем же интерфейсом `get/set/invalidate`.

## 1. Локальный запуск

### Запуск без оплаты и без облачной базы

Отдельный Postgres больше не обязателен. Если `DATABASE_URL` пуст, сервер сам создаёт локальную SQLite-базу в `backend/src/data/navpedagoga.sqlite`. Она сохраняется между перезапусками, поэтому для демо и небольшого реального сервиса не нужны Neon, Supabase, Docker или банковская карта.

### Бэкенд

```bash
cd backend
copy .env.example .env
# DATABASE_URL можно оставить пустым — включится SQLite
# SMARTAPI_API_KEY можно оставить пустым — тогда используется GROQ_API_KEY или офлайн-режим ИИ
npm install
npm start
# сайт и API поднимутся на http://localhost:4000, схема и демо-данные создадутся автоматически
```

Основная конфигурация задаётся в `backend/.env`: `SMARTAPI_API_KEY`, `SMARTAPI_BASE_URL=https://api.smartapi.shop/v1`, `SMARTAPI_MODEL=gpt-5.6-luna`. Если SmartAPI не задан, используется `GROQ_API_KEY` и модель `groq/compound`.

Фронтенд теперь раздаётся тем же Node-сервером. Отдельный `python3 -m http.server` не нужен.

Проверка: откройте `http://localhost:4000` и убедитесь, что `http://localhost:4000/api/health` возвращает JSON с `ok: true`.

Демо-доступ (пароль везде `123456`): `user@np.ru`, `mentor@np.ru`, `admin@np.ru`.

## 2. Публикация в интернете без оплаты

Для публикации с этого ПК в одном окне запустите сервер:

```bash
cd backend
npm start
```

Во втором окне PowerShell:

```powershell
npx --yes localtunnel --port 4000
```

Либо из корня проекта можно запустить готовый `./start-public.ps1`: он сам проверит зависимости, поднимет бэкенд и выдаст новый публичный адрес.

Команда выдаст публичный HTTPS-адрес. Пока работают Node-процесс и туннель, сервис доступен в интернете; база остаётся на этом ПК. Для постоянной работы компьютер должен быть включён.

Если нужен облачный режим, ниже остаётся вариант с бесплатным Render + PostgreSQL.

### 2.1. Облачный бесплатный деплой — пошагово

### Шаг 1. Postgres (Neon или Supabase — бесплатно навсегда)
Создайте проект на [neon.tech](https://neon.tech) (рекомендуется — генерирует connection string сразу с `?sslmode=require`) или [supabase.com](https://supabase.com). Сохраните `DATABASE_URL`.

*Почему не Render Postgres:* его бесплатный тариф удаляется через 90 дней — придётся пересоздавать базу и терять данные.

### Шаг 2. Бэкенд на Render.com (бесплатный Web Service)
1. Залейте весь проект в GitHub-репозиторий.
2. render.com → **New → Blueprint**, укажите репозиторий — `backend/render.yaml` уже настроен на `plan: free`. Либо вручную создайте Docker Web Service с контекстом корня репозитория.
3. В Settings → Environment задайте:
   - `DATABASE_URL` — строка из шага 1;
   - `SMARTAPI_API_KEY` — ключ SmartAPI для `gpt-5.6-luna` (или `GROQ_API_KEY` как резерв);
   - `JWT_SECRET` — Render сгенерирует сам.
4. Важная особенность бесплатного тарифа Render: сервис «засыпает» после 15 минут без трафика и просыпается ~30-60 секунд на первый запрос — это нормально, не баг. Данные при этом не теряются (они в Postgres, не на диске сервиса).
5. Скопируйте публичный URL (`https://ваш-сервис.onrender.com`).

### Шаг 3. Фронтенд на GitHub Pages (бесплатно)
1. В `frontend/index.html` замените:
   ```html
   window.NP_API_BASE = "https://ваш-сервис.onrender.com/api";
   ```
   (обязательно с `/api` на конце — самая частая причина ошибки входа).
2. Залейте содержимое `frontend/` в репозиторий → **Settings → Pages → Deploy from a branch** → `main` / `/ (root)`.
3. Через 1-2 минуты сайт доступен на `https://<логин>.github.io/<репозиторий>/`.

Итого: весь стек (сайт + API + база) — **бесплатно**, с оговорками бесплатных тарифов выбранного AI-шлюза и возможного «засыпания» backend на Render.

## Диагностика проблем

- `https://ваш-бэкенд.onrender.com/api/health` должен отвечать `{"ok":true,...}`. Если нет — Render → Logs.
- Ошибка при входе/регистрации → чаще всего в `NP_API_BASE` не хватает `/api`, либо `DATABASE_URL` не задан/неверен (см. Render → Logs — там будет ошибка подключения к Postgres).
- ИИ отвечает `(офлайн-режим: превышена бесплатная квота)` → квота Groq исчерпана — подождите или проверьте лимиты в панели Groq.
- ИИ отвечает `(офлайн-режим: APIError)` → смотрите Render → Logs сразу после запроса, там `console.error` пишет текст ошибки Groq.

## Конфигурация AI

- SmartAPI подключается через `SMARTAPI_BASE_URL` и `SMARTAPI_API_KEY`, модель — `SMARTAPI_MODEL=gpt-5.6-luna`.
- Ключи читаются только на сервере, никогда не передаются в браузер.
- На фронтенде нет поля для ввода ключа — весь ИИ server-side.
- Не коммитьте `.env` (уже в `.gitignore`).

## Что осознанно не входит в текущую версию (и почему)

Полное ТЗ из диссертации (гл. 3.5) описывает более широкую систему — видеозвонки, интеграцию с VK, email-рассылки приглашений, PDF-сертификаты, публичные рейтинги. Это не реализовано сейчас, потому что требует платной инфраструктуры или существенно расширяет объём:
- **Видеозвонки** — нужен WebRTC TURN-сервер или платный сервис (Twilio/Daily.co); бесплатные лимиты слишком малы для регулярного использования.
- **VK-интеграция и email-рассылки** — требуют либо платного email-сервиса (бесплатные тарифы SMTP очень ограничены по числу писем), либо отдельной регистрации VK-приложения и модерации.
- **PDF-сертификаты** — технически несложно добавить (см. `/mnt/skills/public/pdf` при следующей итерации), просто не было приоритетом в этом проходе.

Чат наставник↔наставляемый и наставник↔ИИ уже реализован (текстовый).

## Модель SmartAPI / Groq

По умолчанию используется `gpt-5.6-luna` через OpenAI-совместимый endpoint SmartAPI: `https://api.smartapi.shop/v1/chat/completions`. Резерв — `groq/compound`, задаётся переменными `GROQ_API_KEY` и `GROQ_MODEL`.

## Новое: постоянно обновляющийся каталог + 6 ИИ-функций

### Постоянно обновляющийся список мероприятий по региону
- Карта считается устаревшей через 4 дня (`STALE_MS` в `roadmap.js`) — при открытии страницы «Дорожная карта» устаревшая карта тихо обновляется в фоне.
- Настоящее расписание — бесплатный **GitHub Actions cron** (`.github/workflows/refresh-roadmaps.yml`), раз в сутки дёргает `POST /api/cron/refresh-roadmaps` (защищён `CRON_SECRET`). Настройка: в репозитории **Settings → Secrets → Actions** добавьте `BACKEND_URL` (URL вашего Render-сервиса без слэша на конце) и `CRON_SECRET` (тот же, что в переменных окружения бэкенда).
- Найденные ИИ мероприятия **хешируются** (`sha256(название|регион|дата)`, колонка `content_hash` в `events`) и попадают в общий каталог без дублей — при повторном поиске один и тот же вебинар не создаётся заново.

### 1 тест после мероприятия
После отметки «Пройдено» появляется кнопка «🧠 Пройти тест» — 5 вопросов, сгенерированных ИИ по материалам мероприятия и методическим рекомендациям Минпросвещения (grounded-поиск), закэшированных на само мероприятие (`event_quizzes`).

### 5 дополнительных ИИ-функций (`backend/src/services/aiFeatures.js`)
1. **Ежедневный дайджест «Что дальше»** на дашборде.
2. **ИИ-ревью черновика отчёта** перед отправкой наставнику.
3. **Методические рекомендации Минпросвещения** по слабой компетенции (карточка на дорожной карте).
4. **Автосборка цифрового портфолио** (этап 6 алгоритма) — раздел в профиле.
5. **Умное напоминание о неактивности** — баннер на дашборде, если давно не заходили.

Все — с офлайн-фолбэком при отсутствии `GROQ_API_KEY`; живой вызов Groq проверяется после запуска сервера с ключом.

### Визуальная карта пути (в духе Duolingo)
Вкладка «Дорожная карта» теперь показывает мероприятия как шаги извилистого пути (`.journey-map` в `styles.css`) — пройдено / текущий шаг / впереди, кликабельно.

## Новое: LMS-функционал для наставника (группы, задания, конструктор тестов, геймификация)

### Группы
Наставник объединяет подтверждённых подопечных в группы («Группы» в меню) — как когорты/курсы в Moodle. Задания можно назначать сразу на группу.

### Конструктор тестов
«Конструктор тестов» — наставник вручную собирает тест: вопрос, варианты ответа, отметка правильного, баллы за вопрос. Не путать с ИИ-тестом после мероприятия (тот генерируется автоматически) — это ручной, полностью контролируемый наставником банк вопросов.

### Задания
«Задания» — наставник назначает либо тест из конструктора (автопроверка), либо свободное задание с текстовым ответом (наставник оценивает вручную, ставит балл и комментарий), на группу и/или отдельных педагогов.

### Виртуальное поощрение (монеты + уровень)
- 🪙 Монеты и XP начисляются автоматически: мероприятие пройдено (+15), тест мероприятия (+10 за верный ответ), диагностика пройдена (+30), отчёт по мероприятию сдан (+15, и ещё +10 если наставник оценил 4-5), задание сдано (+10, и ещё +15 при результате ≥80%).
- Виден в сайдбаре педагога: баланс монет и прогресс-бар до следующего уровня (100 XP = 1 уровень).
- Тарифы и логика — `backend/src/services/gamification.js`, журнал начислений — таблица `coin_transactions`.
- Пока без "магазина трат" монет — это база для будущего расширения (например, разблокировка тем оформления).

Все новые эндпоинты (`/api/groups`, `/api/tests`, `/api/assignments`) протестированы на реальном локальном Postgres: создание группы → добавление участника → конструктор теста → назначение задания на группу → сдача (тест — автопроверка без утечки правильных ответов педагогу; свободное задание — оценка наставником) → начисление монет.
